# B2C1: finite cookie, private-envelope and rotation conformance

This offline source candidate adds 39 named leaf cases to the frozen B3a
94-file baseline. It changes only cookie snapshot ownership and private result
credential-base validation. It does not establish all C01-C42/ABI01-20 conformance,
full B3 acceptance, production cookie portability or consumer readiness.

## Contracts and demonstrated corrections

### Cookie ownership

`NewCookieState`, `Apply` and `Snapshot` now copy mutable cookie storage at their
ownership boundaries. The constructor no longer retains the caller's `Records`
slice; every copied `http.Cookie` also copies its `Unparsed` attribute slice.
Consequently, later mutation of supplied records, supplied cookie attributes or
returned snapshot attributes cannot silently change the owned snapshot without an
`Apply` transition. Strings and value fields retain their existing representation;
nil versus non-nil empty slices are preserved by these copy helpers. Policy
callbacks remain trusted owner inputs, not a hostile-code isolation boundary.

Four reached pre-fix assertions demonstrated these aliases, rather than inferring
a defect from missing tests. The initial failing source hashes and log are retained
in the private `c1b2c1` evidence, together with the corrected-source receipts.

`Apply` still stages the entire cookie/CSRF/revision update and rejects a
contradiction without publishing any part. The new rollback assertions compare
the complete serialized snapshot, not only its revision. Positive `MaxAge` is
converted once to an absolute expiration, then stored with `MaxAge=0`; serialization
and reconstruction must not renew that relative lifetime. These are representation
round trips, not new filesystem or native-store durability qualification.

The generic constructor has no original response URL, capture time or qualified
CSRF provenance parameter. It therefore does not guess a CSRF scope, recompute one
from an arbitrary origin, or reject legitimate multi-origin state because different
origins select different CSRF cookies. A positive multi-origin reconstruction case
retains the exact supplied metadata and independently selects each origin's cookies.
Duplicate replacement is qualified for `Apply` on its exact domain/path/name key;
arbitrary imported duplicate-record semantics and retrospective CSRF provenance
validation are not newly claimed or silently enforced.

### Private credential base

The frozen private ABI already distinguishes `baseCredentialRevision` from
`baseStateRevision`. Checkpoints advance journal state under the held guard, so an
older checkpoint state revision alone must not reject a result. Before returning
a non-null private `credentialDelta`, `AdapterSession.Accept` now checks the
independently issued lease's authority epoch and credential revision against the
current invocation snapshot. A mismatch returns `stale_generation` with the fixed
private detail `credential_base`, without returning the delta or writing storage.

A new negative first issued a valid private lease and durable checkpoint, then
performed a synthetic trusted owner rotation under that same guard. Before the
correction, the old private result was accepted and overwrote that newer context:
the operation returned performed with two credential revisions and two delta
callbacks. After the correction, the newer owner context remains, the old issued
permit is not refunded, and the failed operation retains uncertainty. This tests
the declared unchanged-base rule, not an assertion that a second native writer can
normally enter the held guard. Valid current-base results and journal-only revision
advancement remain accepted.

No exported signature, error category, public/private schema, Node binding or
registry/corpus input changes. `owner.go`, backend/commit, recovery and settlement
implementation files remain unchanged. The incoming lease is still an exact echo
of owner-issued authority, never self-authenticating input.

Lease mutants remain schema-valid and must reach `lease_sequence`; the changed
lease is asserted to differ from the independently owned original. The target
mutation uses the actual digest of a separately parsed registered target. Direction
confusion reflects an otherwise valid outbound invoke frame. Plane cases exercise
the separate schema/entrypoint boundary. Refusal assertions compare storage-call
counts, complete invocation snapshots, sequence and issued dispatches around the
specific invalid input. A replay compares against the state after its first valid
checkpoint, not before that deliberately authorized checkpoint. An ordinary outer
failed-outcome journal is not confused with a private-frame storage admission.

The initial envelope test used `mapValue`, which returns a copy, without assigning
that copy back to the actual frame. Five intended mutants were thus unchanged
positive frames, not demonstrated validator defects. That fixture error and its
red log are preserved. The corrected five mutants passed before production fixes;
a suffix selector also selected `expired_owner_deadline` in that correction run.
Later gates run all 39 cases with the stronger mutation and stage assertions.

The queue fixture attempts the same `MemoryBackend` gate while the first owner
invocation holds it, observes an unavailable acquisition, and only then permits the
first operation to finish its rotation. The follower cannot execute early and must
load the newer credential revision with the same authority epoch. Channel handshakes
replace sleeps; the original queue bound is not increased. This is a synthetic
single-writer queue test, not multiprocess live-issuer or native-backend takeover.
The cursor cases count UTF-8 bytes at the registered boundary and one byte above,
without truncation or any claim about provider-specific cursor compatibility.

## C1a: observed race clean-exit confound in the FD3 fixture

The first required B2C1 full race gate failed after 189.659s because the existing
pre-ACK child test returned `uncertain` instead of `not_dispatched`. That original
red log remains intact. A separately admitted single diagnostic race invocation
used an exact 98-file private copy, four new stage-traced cases and one selected
original before-case. The original failure did not reproduce in that diagnostic;
its passing control is not a waiver or proof of the old final-save timing cause.

The diagnostic did establish a narrower causal fixture confound. The cached Go
runtime calls `racefini` during `os.Exit(0)` but not during nonzero exit. A child
with controlled owner-local test time announced clean exit and was actually reaped
about 1012ms later. With the unchanged real one-second action clock, that same
clean-exit path instead hit its deadline and was killed, despite zero checkpoints,
permits or effects. A nonzero pre-ACK child exited about 1ms after announcing loss,
with a live action context and `not_dispatched`; the post-ACK counterpart retained
one durable permit and returned `uncertain`. All children were reaped, and backend
traces retained original receipt IDs and context/readback observations. The final
save reserve is the existing two-millisecond commit plus two-millisecond cleanup
allowance, four milliseconds total, not a newly increased timeout.

The named FD3 fixture now explicitly models abrupt pre-ACK child loss with exit
code 66; its post-ACK child retains exit code 67. The parent requires the exact
intended exit, a live action context, actual reaping, zero pre-ACK permits/effects
or one post-ACK permit, unchanged before/after certainty assertions and preserved
original journal/receipt history. The real clock, real child, inherited FD and all
production deadlines remain unchanged. No `GORACE` override, controlled clock in
the canonical fixture, production workaround or weakened assertion is introduced.

This correction removes the demonstrated clean-shutdown/deadline conflation. It
does not retroactively claim the exact prior `uncertain` return was reproduced or
fully explained. The changed fixture requires one new exact-source namespace gate
set; its outcomes, including any remaining failure, are recorded in `c1b2c1a`.
At the C1a boundary, all production Go, Node, schema and corpus bytes remained
identical to the B2C1 candidate. The parent verified its 660-record normal gate,
191.791s changed-fixture race gate, vet/format/docs and seven bounded resource
samples. The original 189.659s red remains unchanged and its exact uncertain return
unreproduced. The combined bounded C1 closure does not establish full conformance.
