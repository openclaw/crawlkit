# C1B1: implemented-defect hardening

This source wave fixes review findings R1-R6. It is not complete conformance,
consumer adoption, SDK qualification or release approval. Earlier C1 evidence and
its original source snapshot remain private immutable evidence.

## R1: durable evidence before permission

`Owner.save` requires a matching positive committed receipt and a matching logical
snapshot readback, including operation ID, generation, revision, digest and stored
receipt. A nil Go error, uncertain/not-committed result, stale receipt or old state
cannot authorize a provider effect or private checkpoint ACK. Ambiguous results
use one bounded local reconciliation within the existing operation/cleanup budget;
there is no automatic repeat commit or provider call. Native backend implementations
must preserve the logical Snapshot/receipt contract, not invent successful receipts.

## R2: channel lifetime and admission

Authenticated channels own a cancellation lifetime. Authorization callbacks and
operations inherit it; registration checks liveness atomically. Before-effect
permission checks channel/context again after durable storage and is serialized
with close at its permission boundary. Lifecycle locks are not held across backend
callbacks. Closing before permission prevents dispatch; an already authorized or
uncertain effect still needs reconciliation, not a false stopped result.

## R3: binding-wide durable uncertainty

Inspection reports `uncertain` for unresolved effect journals/claims and
`recovering` for unfinished recovery claims, including after a new owner loads a
protected file. New effects are refused conservatively within that binding.
`OwnerOptions.UncertainReadOperations` is an explicit trusted-owner qualification
of exact existing registered safe-read IDs/versions. Unknown or mutation entries
are rejected. It is not a wire field or caller override, and allowed reads neither
clear nor replace the existing action owner's reconciliation fences. No new action
manager or public fence-clear operation was added.

## R4: actual private/RPC deadlines

Private invoke `budget.phaseDeadline` equals the actual lease deadline, never the
original longer request deadline. `RunPrivateFD` and direct private entrypoints
honor that deadline. `Invocation.CallRPC` is the explicit RPC seam and performs
durable before-effect admission using `maxRpcMs` nested under phase/outer bounds.
`RPCContext` is available to qualified transport wrappers; using it does not itself
grant effect permission. Native `RequestContext`, phase, outer and cleanup budgets
remain distinct. The RPC cap is not applied to unrelated native execution.

## R5/R6: closed branches and matched semantics

Provider-schema qualification analyzes object/array-capable accepting branches,
including nullable unions, references, allOf/anyOf/oneOf, conditional and boolean
schemas. An explicit `additionalProperties` schema qualifies a typed map only when
its values are themselves constrained. Unrestricted maps, object branches and array
items fail closed. Ordinary nullable closed objects and existing fixture schemas
remain accepted. Node dispatches `if` by keyword presence, including boolean false.

The analyzer is bounded to 64 alternative branches, depth64 and 50000 visits.
It conservatively proves closure, not arbitrary JSON Schema satisfiability. Some
complex negative/interdependent constraints that cannot establish closure within
that supported analysis may be refused even if valid JSON Schema; unsupported
keywords and exhausted analysis fail explicitly. Overlapping oneOf branches must
never be treated as a universal anyOf under `not`; a dedicated shared regression
covers this case and its valid explicitly closed counterpart.
